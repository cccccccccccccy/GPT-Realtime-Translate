# 来源追溯与原生交互验证

日期：2026-09-16。对应 v3 的来源追溯、转写更正、固定建议、会后总结和 Markdown 导出要求。

## 实现

- 理解、建议和总结中的发言来源改为可点击的时间与音轨。点击后进入实时记录页，选中并滚动到对应原文；不会自动生成回答或开始采集。
- 新生成的回答保存其引用的转写和研究事实快照；总结保存实际引用的转写快照。更正后显示“已更正”，可以查看生成时的旧原文，同时定位当前版本。
- 旧记录仍可读取；缺少来源版本或事实快照时明确提示，不能把当前研究信息冒充生成时的信息。不存在的来源保持不可用，不跳转到其他发言。
- 固定建议在来源更正后仍保留显示并标为过期。研究信息按“已确认事实”“已确认计划”等类别展示，并保留录入来源。
- 导出 Markdown 的来源链接指向文件内的转写锚点。锚点由片段 ID 的 SHA-256 生成，外部文字不能注入链接目标；发言 ID 和正文均转义。
- 导出保留当前原文、生成时采用且已变化的旧原文、研究事实快照和过期提示。用户录入的研究信息与实际发言、AI 建议分别列出。
- 总结来源必须是已完成片段；未确认的本人片段不能作为“实际回答”证据。负责人和日期为空或只有空白时，界面与导出均显示“待确认”。

来源存在和版本一致不等于语义正确。特别是专家建议是否被接受、引用的本人发言是否真正支持所写结论，仍需要独立质量评估。

## 复现方法

```bash

open build/ResearchCopilotReview.app
```

验证副本顶部始终显示虚构材料提示，启动与设置入口被禁用。退出后内存改动不会保存；重新启动恢复预置材料。需要保留结果时主动导出到项目验证目录。

## 剩余检查

- 在真实会话中新生成的分析、回答与总结的端到端来源一致性，以及并发修订、供应商失败和长上下文场景。
- 有大量建议和历史会议时，快照、列表与导出带来的内存及存储开销。
- Markdown 内部锚点在用户所用阅读器中的实际跳转；本轮检查了链接目标和原生导出，未遍历所有阅读器。
- 历史行内按钮当前可通过鼠标操作；辅助功能树把行内按钮合并在行描述中，后续应改进可访问性。
