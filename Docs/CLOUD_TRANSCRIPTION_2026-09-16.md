# 可选云端语音：恢复与结束处理

更新：2026-09-16。此功能只有用户选择 OpenAI 语音时才会发送音频；默认的 WhisperKit + DeepSeek 流程不依赖 OpenAI Key。

## 本轮实现

云端适配器现位于 `Sources/CopilotSpeech/OpenAITranscriptionProvider.swift`，通过可替换的 WebSocket 传输进行离线故障测试；应用仍使用实际 URLSession 传输。

- 远端和本人轨各有连接、发送队列、事件读取、时间原点和恢复状态。每轨等待发送的音频最多 48,000 个样本（24 kHz 下约 2 秒），另有一个正在发送的帧。积压或明显的输入时间缺口会记为缺口并重建该轨连接，不无限缓存。
- 首次连接必须收到确认所选模型、PCM 格式和 VAD 的 `session.updated`；握手最多等待 15 秒。当前适配 `gpt-live-transcribe`，其他模型在联网前拒绝，避免把不兼容的参数照搬过去。
- 每次采集运行、每轨最多自动重连三次，等待间隔为 1、2、4 秒；成功一次不会重置本次运行的总额度。达到上限后提示手动停止并重新开始。
- 断线时撤销尚未完成的字幕，记录缺口。旧连接的迟到结果不能写入新连接；未确认音频不自动重放，也不切换到其他供应商。恢复期间继续接收的音频只用于更新缺口时间，不积存在内存等待补发。
- 重连后的第一帧重新建立时间原点，转写 ID 加入连接标识，防止服务复用 item ID 时覆盖旧记录。迟到 delta 不延长已经由 `speech_stopped` 确认的结束时间；重复事件在有界缓存中去重。
- 单条消息上限 1 MiB、待完成片段上限 128、单段转写上限 256 KiB。服务器错误正文不写入应用提示或日志。
- URLSession 采用临时会话，禁用缓存、cookie 和系统凭据存储；HTTP 重定向委托拒绝重定向。音频密钥保留在运行期内存和系统钥匙串，不进入导出。

## 停止逻辑

停止后先拒绝新帧、取消重连，两个音轨共同使用 8 秒结束期限：

1. 等待已有发送队列排空。
2. 发送关闭服务器 VAD 的更新，等待对应有效配置确认，以便后续只有一次手动尾部提交。
3. 提交尾部，等候提交确认及所有已知片段的完成事件。
4. 仅当错误对应本次提交且代码为 `input_audio_buffer_commit_empty` 时，将其视为空尾部；继续读取此前仍在等待的片段。
5. 若 VAD 活跃片段在手动提交时换了 item ID，撤销旧暂定字幕并保留其起始时间用于新片段。
6. 超时、空转写或单段失败明确记录可能遗漏；释放连接和运行期凭据。不再固定睡眠两秒后直接关闭。

从未发送过音频的轨道直接关闭，不制造空提交。该结束策略仍需实际服务验证其更新确认、提交确认和在途 VAD 事件的顺序；模拟成功不等于服务器已提供无遗漏保证。

## 已执行的验证

`bash Scripts/test.sh` 共 53 项回归通过。本轮新增 13 项，使用模拟连接，不访问网络或付费 API：

- 最终时间不被后续音频或重复 delta 拉长；连接之间同名 item 不混淆。
- 提交顺序与完成乱序；活跃 VAD 片段变更 item ID 后保留本地时间。
- 空提交错误后仍能收到较早片段的迟到最终文本。
- 结束期限内没有最终文本时记录缺口并关闭。
- 重连不重放旧音频；新的第一帧重新定位时间；重连次数有上限。
- 单轨断开时另一轨仍能完成转写。
- 停止与握手同时发生时不发布“已连接”。
- 发送队列超限时生成缺口，不无限堆积；无音频停止不提交。
- 非有限浮点音频不会写出非法 PCM；非适配模型在请求前拒绝。
- 术语输入中的 LF、CRLF 正确拆分，避免把换行发成单个 keyword。该问题由新增测试发现后修复。

最终将单帧接收上限与总队列的两秒限制统一后，再次运行过载、单轨隔离与重连三项回归，均通过。开发应用已重新打包，并在正常退出旧进程后重新启动，核对主窗口及语音、文字设置界面。此界面检查未启动音频采集或云端调用。

## 官方依据与未验证部分

[Realtime 转写指南](https://developers.openai.com/api/docs/guides/realtime-transcription) 给出了 transcription 会话、24 kHz PCM、增量/完成事件，以及 `gpt-live-transcribe` 的语言和术语提示配置；它也说明跨片段完成事件可能乱序，不提供词级时间戳。

[客户端事件参考](https://developers.openai.com/api/reference/resources/realtime/client-events) 说明空缓冲提交会报错、配置更新需要服务端确认。[服务器事件参考](https://platform.openai.com/docs/api-reference/realtime-server-events/input_audio_buffer/committed?lang=node) 说明 item 与提交/语音边界事件的关系，以及错误关联的客户端 event ID。

需要保留的协议核验项：

- 当前连接路径为 `wss://api.openai.com/v1/realtime?intent=transcription`。已核对 Realtime 会话与事件内容，但本轮官方页面没有完整重述该 transcription 查询参数的握手示例；尚未用真实账户验证此路径。
- 转写指南明确示范 `gpt-live-transcribe` 的 `delay`，通用客户端参考中的部分文字仍只提及旧模型；当前按专门转写指南实现，真实请求仍需检查。
- `input_audio_buffer_commit_empty` 的精确错误码、关闭 VAD 后的尾部事件顺序、服务端重定向和认证失败行为尚未实测。
- 当前时间戳来自 VAD 边界及本地已发送音频的回退时间，并非词级对齐。重连可能丢失上下文和断线期间音频，记录中保留缺口。
- OpenAI 语音凭据、真实 Zoom 音频、网络中断与 90 分钟持续会话尚未完成联调。本轮不得宣称可选云端语音已达到正式会议验收要求。
