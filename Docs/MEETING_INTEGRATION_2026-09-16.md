## 输入与隔离范围

- 固定输入为 [timepoint.txt](../Fixtures/ASR/timepoint.txt) 和 [necrosis.txt](../Fixtures/ASR/necrosis.txt) 对应的既有合成音频，主题是时间点与组织学验证，以及可逆缺血与坏死的区分。
- 使用实际 `MeetingController`、默认本地 WhisperKit 模型及默认 DeepSeek 文字接口；会执行翻译、理解、回答生成、独立回答核对和总结。
- 音频源替换为按实时节奏推送的固定文件，存储替换为独立内存实现。不会采集 Zoom 或麦克风，不加载用户保存的会议、设置或研究背景。
- 研究身份与背景为明确的虚构测试说明，已确认研究事实和计划为空；默认术语表只作为词汇背景。
- 凭据仅由生产代码从钥匙串读取并用于 `https://api.deepseek.com` 的认证，不打印或写入报告。发送的是合成转写、默认词汇背景及其派生文字，不上传音频。
- 参考文本和关键短语标签只进入评测器，不传给语音识别或文字模型。保留 `irreversible` 已知误识别，不手工替词制造通过结果。

## 运行方法

先确认允许本轮付费 API 调用。需要缓存模型路径 `.build/models/prepared-model-path.txt`、已有合成音频，以及应用中保存的默认 DeepSeek 凭据。

```bash
RESEARCH_COPILOT_LIVE_E2E=1 \
RESEARCH_COPILOT_E2E_OUTPUT="$PWD/.build/meeting-integration-v1" \
bash Scripts/test.sh --filter syntheticLocalSpeechToDeepSeekMeeting
```

输出目录必须为空；已有报告时拒绝运行。后续复测使用新的目录，不覆盖失败证据。两条样例顺序运行；各自写入 JSON 检查点和最终 Markdown 导出。模型加载时间单独记录，播放结束后最多等待约 70 秒处理时间；整个测试设有十分钟上限。

## 报告解释

所有阶段时间均相对模拟音源开始，以约 50 毫秒轮询读取控制器发布的状态。它们没有测量 SwiftUI 实际绘制、Zoom 网络传输或真实声卡捕获延迟。

| 字段 | 含义 |
| --- | --- |
| `firstTextSeconds` | 首次观察到任意非空转写 |
| `firstPartialSeconds` | 首次观察到未完成转写；可能不存在，不能用 final 冒充 |
| `firstFinalSeconds` | 首次观察到完成片段；不一定是整个问题结束 |
| `firstTranslationSeconds` | 首次观察到与当前修订一致的翻译 |
| `analysisSeconds` / `analysis` | 首次理解分析的观察时间和对应结果 |
| `latestAnalysis` | 结束时控制器持有的分析，可能与首次结果不同 |
| `firstEnglishDraftSeconds` | 首次观察到流式英文草稿；该草稿尚未核对 |
| `answerPublishedSeconds` | 首次观察到经过核对并正式发布的回答建议 |
| `lastVoiceSeconds` | 按固定 100 毫秒块、RMS 阈值 0.008 估计的合成问题最后有声位置 |
| `answerAfterLastVoiceSeconds` | 正式建议发布时刻减去上述最后有声位置；仅为控制器延迟代理值 |
| `manualAnswerRequestedSeconds` | 自动分析明确拒绝回应或失败后，一次手动请求的时间；只在文件播放结束后触发 |
| `automaticAnswerPublished` | 首次发布是否发生在诊断发起手动请求之前；不能替代语义上的自动回应正确率 |
| `summarySeconds` | 停止后生成总结的独立耗时，不计入回答延迟 |
| `pipelineOutputComplete` | 是否有分析、回答、全部 final 翻译、总结、内存保存且只含远端轨；仅代表流程产出完整 |
| `metrics` | 原始转写 WER、CER 和所列关键短语保留情况 |
| `finished` | 诊断正常收尾，不代表质量验收通过 |

失败和中间状态同样保留；单独检查 `errors`、来源、总结中的本人回答/决定/行动，以及未确认的研究表述。即使流程产出完整，也不能据此认定文本事实正确。测试不替代人工审核的保留集、真实 Zoom 端到端 P50/P95、双轨、设备切换或 90 分钟稳定性验收。

实现见 [LiveMeetingDiagnosticsTests.swift](../Tests/ResearchCopilotTests/LiveMeetingDiagnosticsTests.swift)。完整待办仍以 [v3 实施状态](IMPLEMENTATION_STATUS.md) 为准。

## 实际运行记录（2026-09-16 晚，Kimi3 接手后）

用户在交接后明确授权本轮将两条虚构合成问题的转写文本发送至 DeepSeek。三轮输出目录均完整保留，未覆盖：`meeting-integration-v1`（沙箱环境失败）、`meeting-integration-v2`（基线）、`meeting-integration-v3`（控制器修复后复测）。

### 第 1 轮（v1）：执行环境失败，非产品错误

在禁止写入 `~/Library/Caches` 的沙箱中运行，Core ML（Espresso）报 `create_directories: Operation not permitted`，WhisperKit 未产出任何转写：timepoint 零片段、WER 1.0，necrosis 未收尾。无 DeepSeek 调用发生。此失败归类为执行环境限制，与产品错误分开记录，符合交接计划对额外沙箱的要求。

### 第 2 轮（v2）：正常 macOS 权限基线

模型准备 52.4 秒（首次 Core ML 编译，含冷启动），第二条 fixture 起降至约 2.1 秒。

- **timepoint**：ASR 与参考完全一致（WER 0，关键短语齐全）。翻译 39.5 秒（受首次 final 38.4 秒拖累）、分析 40.4 秒正确判定为“需用户回应的问题”。英文草稿 44.1 秒产生，但独立核对以三条理由驳回（把信息缺失表述为“未提供”的状态主张、元讨论“我掌握的信息”、未提出澄清问题）。无回答发布；诊断的手动兜底按设计不覆盖核对驳回场景。总结正常。
- **necrosis**：全流程完成。保留已知 ASR 错误 `irreversible → a reversible muscle injury`（WER 2/27）；该反转经翻译、分析原样传导（“可逆性肌肉损伤”），回答实际针对的是与原意相反的问题——关键 ASR 错误的下游影响首次在完整链路中实测确认。回答经核对通过并发布，发布时刻距最后有声 12.0 秒。总结正常。
- 诊断自身收尾正常，失败与成功均完整保留，手动/自动归因字段准确（本轮 `automaticAnswerPublished=true`）。

### 控制器修复：核对驳回后带反馈重生成一次

v2 暴露真实集成缺陷：真实问题若草稿被核对驳回，用户只能看到错误、无任何建议，没有恢复路径。已在 `MeetingController.generateAnswer` 中加入**仅一次**的带核对反馈重生成；第二次草稿仍须通过同一证据校验与独立核对，再次被驳回则按原路径报错。安全边界不变，仅在被驳回路径增加一次 API 调用。88 项普通回归通过（另 1 项本诊断默认跳过）。

### 第 3 轮（v3）：修复后复测，未宣称改善

- **timepoint**：重生成机制实际执行（第二次草稿文本不同，新驳回理由针对新文本“from the study records”暗示存在研究记录），仍被驳回，错误如实上抛。机制符合设计，但本轮未转化为发布。
- **necrosis**：自动分析本轮判定无需回应（与 v2 相反，分析模型输出波动），诊断的手动补请求兜底首次真实执行并正确归因；手动草稿同样被核对驳回（把“计划对比影像与组织病理”当作已确认计划）。
- 结论：回答发布的主要瓶颈是**回答模型在空研究事实场景的稳定合规性**与**核对模型尺度偏严且轮次间波动**，而非控制器。v2 曾通过的谨慎表述在 v3 同类表述被驳回，说明核对边界不一致。该问题转入回应质量工作包，需要以人工保留集量化，而不是反复重跑本诊断择优。
- **延迟（热缓存单样本，仅供参考）**：timepoint firstFinal 7.8 秒（音频 5.5 秒）、分析 10.0、草稿 14.5；necrosis firstFinal 13.1（最后有声 11.1）、分析 15.1、草稿 23.7。链路为“ASR final → 分析 → 回答 → 核对”全串行，即使全部成功，建议就绪估算在最后有声后 8–14 秒，**当前串行结构达不到 v3 的 P50 ≤4 秒 / P95 ≤8 秒目标**。需要流水线化（partial 阶段提前分析/起草）或更快模型；这是架构级发现，两个样例不足以形成分位数。
