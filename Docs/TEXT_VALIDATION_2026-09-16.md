默认端点为 `https://api.deepseek.com`，翻译/理解/内容核对使用 `deepseek-flash`，回答/总结使用 `deepseek-v4-pro`。本次响应证明测试时账户可调用这些模型，不代表未来额度或所有任务质量。

虚构材料：明确点名 Dr. Chen，询问如何用组织学验证影像变化。唯一确认计划是“将影像发现与组织学比较”；本人轨另外记录这句话，用于检验总结中的实际回答。语义评测应使用独立保留集，本例只做开发诊断。

这是一轮固定材料实测，不是 60 条人工标注评测，不证明未来输出均正确。回答耗时包含生成与核对；未包含录音、分段、ASR、自动意图分析，不可当作 v3 的问题结束至建议显示延迟。当前单次回答请求已超过 4 秒，因此不能宣称端到端 P50 目标达标。

## 必须保留的失败历史

| 轮次 | 自动检查 / 人工式逐句检查发现 | 修正 |
| --- | --- | --- |
| 初始 `deepseek-functional.json` | 结构通过，但理解/总结使用英文，回答重复专家问题 | 明确各字段语言、回应角色及已确认计划使用 |
| v2 | 翻译通过，理解未归为对用户提问；旧程序提前退出，没有保存完整报告 | 将无称呼的“you”改为点名虚构研究者；后续保留失败结果并继续其余任务 |
| v3 | 回答正文合理，但 `sourceIDs` 为空，来源校验拒绝 | 明确问题来源和事实来源各自必填的职责 |
| v4 | 结构通过，但口述回答包含“supplied information”等助手措辞 | 将缺失背景提示留在中文说明 |
| v5 | 结构通过，但中文变为问题概述；英文把缺失背景写成研究步骤尚未确定 | 为中文翻译与不同回答版本增加具体字段说明 |
| v6 | 结构通过，但把术语表中的坏死/灌注扩写为研究计划 | 明确术语不是研究事实，并加入独立事实与中英文核对 |
| v7 | 固定正例通过；固定虚构研究终点被拒绝 | 作为当前结果保留；仍需独立语料评测 |

这里的逐句检查由开发代理完成，不冒充用户或医学专家的人工标注。v4、v5、v6 报告中的“未出现 failure”只表示当时自动检查通过；上表记录的语义缺陷仍属于失败，不能从报告字段误读为正式验收通过。

## 当前发布建议的条件

1. JSON 能正确解析，引用真实来源，引用的研究事实属于已确认事实或计划；数字检查通过。
2. 同一供应商的快速模型另做核对，检查各英文版本是否有依据、未知是否被写成未完成、中英文是否一致、回答对象是否正确。
3. 核对明确批准且问题列表为空，应用才保存/显示为完成建议；失败、断流、异常或取消时不发布新建议。
4. 候选流式文本只作为“尚未校验”的草稿显示。复制/固定不代表用户实际说过，不能据此进入实际发言总结。

额外核对不带入术语表或未确认课题背景作为证据。它会增加一次 API 请求与延迟，仍可能误判或漏判，不能当作零幻觉证明。没有自动切换供应商或将内容发送到第二家公司。

## 复现

先编译诊断程序，确保应用设置中已经保存默认 DeepSeek 端点凭据。macOS 可能要求确认独立诊断程序的钥匙串访问，不需要把 Key 放进终端或聊天。

```bash
bash Scripts/test.sh
.build/debug/CopilotDiagnostics test-text --provider deepSeek \
  --check-answer-guard --report .build/benchmarks-repeat/deepseek.json
```

四项功能通常共五次请求，额外负例增加一次；遇到格式错误或限流时可能有有界重试，按实际用量计费。失败结果会写入报告，退出码为 1。自定义端点/模型通过应用内设置测试。

后续必须用不少于 60 条经人工标注的保留材料检查回应精确率、召回率及事实错误，并验证修订、取消、长上下文、总结和真实 Zoom 端到端行为。
