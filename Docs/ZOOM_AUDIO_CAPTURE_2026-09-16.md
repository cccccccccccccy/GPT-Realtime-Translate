## 本轮实现

- 主窗口新增“检测 Zoom 音源（30 秒）”，无需模型和 API Key。每帧仅计算计数与 RMS；不保存音频，不创建会议记录，不启动 ASR 或文字服务。报告只含时间、应用标识、计数、音量和受控错误信息。
- 检测始终明确传入 `microphone: false`，与“默认记录我的发言”的设置分开；30 秒后自动停止，也可手动结束。
- 启动中点击停止会记住取消请求，待启动返回后立即停止。检测期间禁止新建/切换会议及启动第二条采集。
- 停止或关闭本人轨时先关闭音频转交入口；若系统停止调用失败，保留流对象供重试，显示“停止尚未确认”，禁止开始新采集，正常退出也等待处理。
- 权限预检同时显示录屏与系统录音、本人的麦克风授权。只有 ScreenCaptureKit 的权限拒绝才显示权限错误；音源消失、显示器缺失及其他系统错误分别处理，不输出平台错误中的原始文本。

代码：`AudioSourceProbe.swift`、`CaptureReadiness.swift`、`AudioCaptureService.swift`、`MeetingController.swift`、`ResearchCopilotApp.swift`。

## 权限与开发签名问题

本次由用户明确授权“录屏与系统录音”，并亲自完成 macOS 身份验证。其他应用权限未改变，未请求副驾麦克风权限。

首次授权后，系统设置显示开关开启，但新版进程仍收到权限拒绝。仅过滤本应用的 TCC 日志后确认：系统仍要求旧构建的签名哈希 `17060de467a5692db751bcd13f227380481a1942`，而当前构建为 `37ba13120f81fd8d45a3c795cf0d8fb31b0ec2aa`。单纯切换开关和重新添加应用未立即更新旧绑定。

只重置该应用的 ScreenCapture 授权记录，随后重新授权并重新打开应用，预检转为“已允许”，音源枚举和捕获成功。使用的重置命令仅撤销这一项旧记录，不会自行授予权限：

```bash
tccutil reset ScreenCapture org.researchcopilot.app
```

这不是每次启动都应执行的操作，也不应重置所有应用的隐私权限。开发版采用 ad-hoc 签名，重新编译后可能再次需要授权；正式开发/发布应使用稳定的 Apple 签名身份。Apple 工程师对 ad-hoc 构建被视为新应用的说明见[开发者论坛](https://developer.apple.com/forums/thread/819406)。

构建脚本支持可选 `RESEARCH_COPILOT_SIGNING_IDENTITY`，可指定本机已有、适用于此项目的 Apple 签名身份；未设置时仍使用 ad-hoc。此选项不创建证书、不登录 Apple 账户，也不代表已经完成正式签名或公证。本次实测应用仍是 ad-hoc 构建。
