# 本地语音实测记录（2026-09-16）

## 方法与环境

MacBook Air / Apple M4 / 16 GB，macOS 26.5.2，Swift 6.3.3；argmax-oss-swift 固定 1.1.0。模型目录标识 `large-v3-v20240930_626MB`，权重约 606 MiB，另有分词文件；不从文件名推断运行内存或识别质量。

材料见 [Fixtures/ASR](../Fixtures/ASR/README.md)，由 macOS Samantha、Daniel、Tingting 合成，没有录制真实会议。以 100 ms 帧按播放速度输入生产识别管线；双轨同时输入英语和中文。没有通过 Zoom 捕获，因此不是会议端到端测试。

模型已准备、诊断程序已编译后，在项目根目录运行：

```bash
/usr/bin/sandbox-exec -p '(version 1) (allow default) (deny network*)' \
  /bin/bash Scripts/run-asr-benchmarks.sh .build/models .build/benchmarks-repeat
```

只禁止测试进程联网，允许系统 Core ML / GPU 访问；未改变整机网络。开发工具默认沙箱禁止这些资源时，曾导致模型加载失败。

WER 按词元计算，不自动等价化 `six/6`、`mm/millimeters`。CER 去除空白、标点与大小写，不转换繁简体。中文 WER 的空白分词不适用，不用于质量判断。

final 延迟为事件到达时间减去识别出的末词结束时间，按诊断进程时钟测量。双轨按事件发出顺序为本人首段、远端、本人尾段；首个 partial 未按音轨分别统计。这不是人工对齐延迟或回答建议延迟，样本不足以估算具有代表性的 P50/P95。

冷准备约 54.94 秒，同轮后续缓存加载约 2.06–2.08 秒。首次下载与 Core ML 专用编译须在会前完成。RSS 包括准备阶段，只计该进程，不等于完整 GPU/ANE 或整机内存。

四组没有记录队列丢弃或处理异常；这不证明不存在识别错误、遗漏或真实会议故障。

## 关键问题

- **含义反转未解决**：参考音频为 `irreversible muscle injury`，模型输出 `a reversible muscle injury`。较低 WER 仍可掩盖严重错误，此项阻止宣称医学会议质量达标。未用自动替词或修改参考答案消除错误。
- 数字样例的两处 WER 来自拼写/单位缩写差异；该例中的 48 小时、30 而非 13、`do not prove` 均保留，不能推断其他数字均可靠。
- 中文只有一段清晰合成材料；CER=0 不能推断口音、噪声、回声或重叠发言的表现。
- 本人尾段接近 6 秒。与 Zoom / 幻灯片并行的持续调度与负载尚未测量。

## 失败与迭代记录

| 目录 | 发现 | 处理 |
| --- | --- | --- |
| `.build/benchmarks` | nil 语言没有自动开启依赖的语言检测，中文尾段出现英文 | 本人轨显式启用语言检测 |
| `.build/benchmarks-v2` | 长术语提示导致词时间戳对齐行偏移，final 几乎为空 | 增加固定依赖适配与回归 |
| `.build/benchmarks-v3` | 修正对齐后恢复文本，长提示仍增加重复、延迟和中文错误 | 应用默认关闭长 ASR 提示 |
| `.build/benchmarks-v4` | 中文改善，英语关键错误仍存在 | 保留为基线 |
| `.build/benchmarks-v5` | 空/无效 final 显示遗漏，正常重叠不报假缺口 | 四组复测完成；结果另存，不覆盖基线 |

v5 复测期间发生文字模块重建，部分后续进程再次进行 Core ML 冷准备；不据此推断遗漏检查的性能影响。精确结果见 `Validation/2026-09-16/asr-v5/`。

提示词对齐适配针对固定依赖版本，升级后须复核。术语表仍用于文字任务，诊断保留 `--use-glossary` 供比较。遗漏提示只表示音频活动未得到有效文本，可能包括噪声，不等于精确的漏词检测。

模型 SHA-256 记录是首次本机导入后的完整性基线，不是发布者签名。后续已加入严格离线分词加载和默认资源提交固定，见[模型准备说明](MODEL_PREPARATION.md)；真实 Zoom + 幻灯片 + 副驾 90 分钟验收仍待完成。

## 关键字词与时间定位后续检查

已增加六个单轨样例与一组中英双轨的短提示对照，以及显式关键短语检查。发现并修复了后处理丢弃零时长词、从而删除 `I'm not` 的问题；片段会标注时间定位不精确。默认模型的 `irreversible` 误识别仍存在，短提示没有解决它，且存在重复与中文退化，因此默认不启用。完整的前后两轮 28 次报告见[关键字词验证](ASR_CRITICAL_WORDS_2026-09-16.md)。

旧报告没有传入关键短语表，不能把其中的 `missingCriticalTerms: []` 当作全部重要词语正确。新报告明确记录实际检查范围和输入文件哈希。模型对出错词也给出了约 0.99 的逐词分数，未经校准的分数不应被呈现为正确率。

后续另完成 32 层解码器的 `openai_whisper-large-v3_947MB` 七组禁网比较。两处关键术语错误仍相同，字面 WER 的一词改善仅涉及单位写法；双轨最长 final 延迟约 24.13 秒、中文 CER 3.39%，不支持直接替换默认模型。结果与局限见[完整 large-v3 比较](ASR_CRITICAL_WORDS_2026-09-16.md#完整-large-v3-压缩模型比较)。
