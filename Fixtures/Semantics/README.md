# 语义测试集与评测

[cases.json](cases.json) 包含 60 条自动拟定的虚构开发用例，**全部待人工审核，不能计入 v3 的人工标注验收集**。包含原计划的“时间点与组织学验证”和“可逆缺血与不可逆损伤”两条重点问题。未使用真实会议、个人研究资料或 API Key。

| 类型 | 数量 |
| --- | ---: |
| 直接提问 | 8 |
| 间接质疑 | 8 |
| 背景、寒暄及引用指令 | 8 |
| 建议 | 6 |
| 对他人的问题 | 6 |
| 本人发言 | 6 |
| 信息缺失 | 8 |
| 信息冲突 | 4 |
| 长问题、多片段及转写修订 | 6 |

## 用例结构

每条用例包含虚构身份、术语表、带确认状态的研究事实、按接收顺序排列的转写事件、选中片段，以及独立的预期标签和人工评阅要点。

- `events` 通过生产代码的 `MeetingSession.upsert` 重放；重复及过期版本不得覆盖稳定转写。修订用例只将重放后的最新片段送给模型。这不等于已验证界面中的异步请求取消。
- `expected.shouldOfferAnswer` 表示是否应为用户自动生成回应建议；`addressee` 和 `acceptableKinds` 分别用于对象与类型检查。
- `answerRubric`、`forbiddenClaims` 是中文评阅要点，不是模型输入，也不通过关键词匹配宣称答案语义正确。
- `review.status` 默认 `draft`；人工核实后才能改成 `humanReviewed`，并填写审核人和 ISO 8601 审核时间。
- `partition` 当前全为 `development`。这些用例已经用于开发，不能事后改名成未见过的保留测试集。正式验收需另外组织至少 60 条人工审核、未用于调参的 `holdout` 用例。

## 运行

在项目根目录执行，先用 `bash Scripts/test.sh` 构建诊断程序。

```bash
# 离线校验结构、重复 ID、人工审核记录和转写重放，不访问密钥。
.build/debug/CopilotDiagnostics validate-semantics \
  --corpus Fixtures/Semantics/cases.json

# 开发测试：显式包含草稿，调用默认 DeepSeek 快速模型。
.build/debug/CopilotDiagnostics test-semantics \
  --corpus Fixtures/Semantics/cases.json --provider deepSeek \
  --include-drafts --report .build/benchmarks/semantic-draft.json
```

文字测试会向选定供应商发送用例中的身份、研究背景、事实及转写，产生 API 用量；默认只执行理解分类。凭据来自应用已保存的该供应商默认端点钥匙串条目。不会读取实际会议和应用研究背景。不要把真实敏感资料混入这个虚构测试集。

`--limit N` 限制按文件顺序执行的数量；`--answers` 对模型判断需要用户回应的远端用例另外生成答案并调用同供应商的事实/中英文核对。漏报问题不会生成答案，会在召回率中暴露。格式修复重试可能增加请求数量。

不加 `--include-drafts` 时只运行已人工审核的用例；当前测试集会在读取凭据和 API 调用之前报“没有经人工审核的语义用例”。可使用 `--provider openAI` 测试其默认端点，但尚未完成该供应商实测。自定义模型/端点仍通过应用测试。

报告每完成一例就原子写入。`requestedCaseIDs` 记录本轮计划，`completed` 区分完整运行与中断；`completed=true` 只说明全部已执行，不等于全部正确。单例失败保留并继续，取消则停止；报告不含密钥。测试报告不能覆盖输入测试集。

## 阅读结果与人工审核

报告按“草稿/人工审核”与“开发/保留”分别统计，不混在一起。精确率和召回率只在有有效分类的用例上计算，因此必须同时查看 `failedAnalyses`、`coverage` 和 `correctDecisionsPerAttempt`；分母为零时比例为 `null`。API 调用成功也不等于分类正确，进程退出码为 0 不能代替指标检查。

每例保留结构化分类、答案候选、模型核对结果、失败原因和请求哈希；语义预期标签留在本地报告，便于对照。候选被拒绝时仍保留，不能只评阅最后被采用的答案。尚未生成答案的用例也没有事实正确性的证据。

人工审核应逐例确认：

1. 回应对象和是否需要回应；对含糊情形允许修改标签及理由，不强迫二选一消除歧义。
2. 核心问题是否完整，数字、单位、否定、计划与已完成状态是否保留。
3. 每一种英文答案是否可由用户直接说出，是否夹带没有来源的研究结果、方法、终点、承诺或“尚未完成”。
4. 中文是否忠实翻译英文；澄清问题是否问专家的意图，而非向专家索取用户自己的实验信息。
5. 是否把专家建议、AI 建议、术语表或冲突记录擅自升级为已确认事实。

人工答案评估可另存表格，包含 `caseID`、报告 SHA-256、审核人、时间、结论和具体错误。报告中的 `humanAnswerAssessment` 初始均为 `pending`；模型核对不能填成人工通过。

v3 验收要求在明确人工标签的保留集上回应精确率和召回率均不低于 90%，且研究事实测试不得出现无依据的具体结果、数据或承诺。本工具不自动宣布整体验收通过；还需逐类错误、失败覆盖率与人工答案审核。本轮为纯文本测试，不测 ASR、真实 Zoom、界面调度或端到端延迟。
